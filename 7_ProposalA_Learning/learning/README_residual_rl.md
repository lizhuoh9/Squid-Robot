# 별도 강화학습 보정

현재 제안서 A와 기존 딥러닝 보정을 고정한 상태에서 PPO로 두 번째 보정 정책을 학습한다.

`effort = A 기본 출력 + 기존 딥러닝 보정 + 강화학습 보정`

- 기존 딥러닝 deployed 한도: ±0.5cm/s². 현재 연구용 재학습 후보는 ±0.8cm/s²이며 기존 ESP-DL/펌웨어 설정에는 반영되지 않았다.
- 강화학습 한도: ±0.8cm/s²
- 두 보정의 합산 제한 없음. 각 모델 한도에 따른 합계 범위는 ±1.3cm/s²다.
- 최종 구동 duty만 ±100%로 제한한다.
- 기존 음수 딥러닝 차단은 기존 모델에만 적용한다. 별도 RL 출력은 입력 범위 보호와 ±0.8 한도를 적용한다.

## 실행

프로젝트 `7_ProposalA_Learning` 폴더에서:

```powershell
python -B learning/residual_rl.py --updates 240 --envs 64
```

결과는 `artifacts/residual_rl_v1`에 저장한다. 동일 명령을 다시 실행하면 이 폴더의 결과를 덮어쓴다.

| 파일 | 용도 |
|---|---|
| actor.pt | 배포 검증을 통과해 저장한 정책 또는 이전에 명시적으로 승인한 시험 모델. 128→32→16→1, 출력 tanh×0.8 |
| candidate.pt | 조건 미통과 연구용 후보. actor.pt를 덮어쓰지 않으며 새 배포 모델로 변환할 수 없음 |
| ppo_training_state.pt | 마지막 PPO 업데이트의 정책·가치함수·최적화 상태. RNG 상태는 미포함 |
| training_report.json | 데이터 출처, 고정 모델 해시, 학습 이력, 기존 방식과 비교 결과 |

입력은 기존 정규화 특성 125개, 실제 적용된 NN 보정값을 해당 연구 후보 한도로 나눈 값, 직전 RL 보정값, 현재 절대 수심으로 총 128개다. 미래 센서나 미래 기록 명령은 입력하지 않는다. NN 한도가 바뀐 후보는 ESP-DL 입력 정규화와 펌웨어 한도를 함께 갱신하고 다시 빌드하기 전까지 기존 펌웨어와 짝지어 사용할 수 없다.

학습은 기존 동역학 보고서에 지정된 전체 기록 단위 분리를 유지한다. train만 PPO 환경 초기화에 사용한다. 50%는 목표 근처 저속 상태, 25%는 오차 4cm·속도 6cm/s 이내, 25%는 전체 train에서 뽑는다. 매 학습 궤적에 같은 초기 상태·모델·물리 조건의 기존 제어 궤적을 함께 실행한다. 두 궤적 보상의 차이와 정규화한 양쪽 최대 이탈 점수 차이를 학습해, 초기 상태가 어려운 것과 RL이 악화시킨 것을 구분한다.

validation에서 양쪽 최대 이탈 개선과 다른 지표 비악화 조건을 통과한 정책을 우선 선택한다. 다음 우선순위는 양쪽 최대 이탈 중 큰 값(cm), 두 최대 이탈 합(cm), 목표 근처 평균 오차, 보상이다. 가중합이 아닌 사전식 순서라 평균 오차 개선으로 더 나쁜 최대 이탈을 상쇄할 수 없다. 아무 정책도 통과하지 못하면 candidate.pt만 저장한다. 선택 후 test를 평가한다. 최근 수중 로그를 추가로 읽거나 동역학 모델을 재학습하지 않는다.

`python -B learning/reselect_residual_rl.py`는 선택 기준 수정 시 저장되어 있는 초기화·이전 선택·마지막 PPO 상태만 validation에서 다시 비교한다. 모든 중간 업데이트 가중치를 복원하는 기능은 아니다. `python -B learning/diagnose_residual_rl.py`는 선택 완료 후 동일 초기 상태의 4초·12초 비교와 잘못된 보정의 시간별 추적을 `diagnostics.json`에 저장한다. 진단 결과를 독립적인 새 테스트로 취급하지 않는다.

정책은 train만 사용한 보정 여력 확인에서 찾은 위치·속도 제동 방향으로 초기화하고, PPO가 모든 가중치를 조정한다. 초기화 정책 자체도 검증 후보에 포함하며, 그 정책이 최종 선택된 경우 보고서에 PPO 학습 결과로 표기하지 않는다.

보상은 양쪽 수심 오차(가중치 7), 1.5초 정속 예상 오차(가중치 2), 속도, 목표 근접/정착 보상을 사용한다. 매 제어 단계에서 기존 A+NN과 같은 시작 상태로 비교하고, 기존 제어 대비 **얕은 쪽·깊은 쪽 중 절대 최대 이탈(cm)의 제곱 증가**에 벌점을 준다(가중치 100). 펌프 방향 전환 벌점은 20으로 높여 진동을 줄이도록 한다. RL 출력과 출력 변화에도 벌점을 준다. 학습 보상은 1/50로 스케일하며 보고서의 물리 비용은 원래 단위다. 물리 모델은 50ms, 제어는 100ms, 에피소드는 12초다. 방향 전환 지표는 4초당 횟수로 정규화해 표시한다. 기존 펄스와 제어 이득, bias 감소를 시뮬레이션에 포함한다.

## 결과 해석

`acceptance_passed`가 true여도 실제 수중 성능을 보장하지 않는다. 평균 오차뿐 아니라 얕은 쪽 이탈, 깊은 쪽 최대 이탈, 전환 횟수, 목표 근처 오차도 확인해야 한다. 정책이 실패한 경우 자동으로 0 정책으로 바꿔 성공처럼 표시하지 않는다.

ESP-DL 변환과 로컬 펌웨어 연결까지 지원한다. 기존 `hybrid_mpc_v1` 모델 파일은 바꾸지 않는다.

```powershell
# 기본 변환은 RL OFF다.
python -B learning/export_residual_rl.py
# 사용자가 승인한 미검증 시험용 ON 빌드의 경우에만 사용한다.
python -B learning/export_residual_rl.py --enable --allow-unvalidated
```

추가 파일은 `residual_rl.onnx`, `residual_rl.espdl`, `ResidualRLConfig.h`, `espdl_validation.json`이다. ONNX/ESP-DL에는 actor의 마지막 선형층까지 포함하고, 펌웨어에서 출력 logit에 tanh×0.8을 적용한다. train 롤아웃만 INT8 보정에 사용하고 별도 validation/test 출력 차이와 폐루프 결과를 평가한다.

펌웨어는 기존 추론 작업에서 NN→RL 순으로 실행한다. RL 입력에는 같은 요청의 NN 결과를 얕은 위치 차단한 값과 마지막으로 수신·사용한 유효 RL 결과를 넣는다. 입력 오류, 이력 미준비, 세대 불일치 또는 250ms 초과 결과에서는 RL을 사용하지 않는다. RL 모델 로딩 실패는 기존 NN 단독 동작으로 남는다. `/capture/status`의 `rl_enabled`, `rl_ready`로 설정과 로딩 준비 상태를 구분한다.

기존 CSV의 `dl_correction_cm_s2`, `dl_applied`는 NN만 나타낸다. RL 보정은 별도 getter로 제공하며 기존 CSV 열이나 HC-12 기록 주기는 바꾸지 않았다. 실제 펌웨어는 센서 새 샘플에 맞춰 비동기 추론 결과를 사용하므로 시뮬레이션의 동기 100ms 즉시 결과와 차이가 있다.

로컬 빌드는 실제 기기 추론 시간·메모리 여유·수중 성능 확인이 아니다. 이번 작업에는 업로드가 포함되지 않는다. `integration_report.json`이 로컬 빌드 상태를 설명한다.

기존 학습 동역학의 오차, 센서 지연의 근사, 200ms 방향 전환 잠금 가정의 한계가 있다. 12초 예측은 3초 데이터 창으로 학습한 모델을 더 길게 외삽하므로 오차가 누적될 수 있다. 기존 평가 데이터는 이전 개발에서도 사용돼 완전히 새로운 독립 검증으로 볼 수 없다. 이전 4초 지표와 새 12초 지표, 실제 수중 CSV 오차를 직접 비교하면 안 된다.
